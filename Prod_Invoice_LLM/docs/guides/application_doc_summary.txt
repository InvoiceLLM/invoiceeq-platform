Here's the reading order, grouped by what each phase builds toward:

1. Big picture (10 min)

	README.md — repo structure, tech stack, team roles
	docs/architecture/Technical_Architecture_Document.md — the core architecture doc, describing the target system end-to-end
	docs/architecture/Cloud_Architecture_Document.md — Azure infra picture

2. Data & API contracts (source of truth for anything code-level)

	3. docs/architecture/Database_Schema_Document.md — full relational + vector schema
	4. apps/invoice-be/Backend_Code_Layout_Document.md — endpoint → file → function call flow for every API

3. Process (read once, not per-feature)

	5. docs/guides/workflow.md (short form) / docs/guides/detailed_workflow.md (full process) — how feature tracking/review works in this repo

4. Feature-by-feature detail — backend first

	6. apps/invoice-be/docs/be_features_tracker.md — status index and the single source of truth for open implementation items
	7. Individual apps/invoice-be/docs/feature_1..11_*.md files, in numeric order — target design for each feature

5. Frontend
	8. apps/invoice-fe/docs/fe_features_tracker.md
	9. Individual apps/invoice-fe/docs/feature_1..7_*.md files, in order

6. Website
	10. apps/invoice-website/website_features/website_features_tracker.md
	11. apps/invoice-website/website_features/feature_1..4_*.md, in order

7. App-level implementation READMEs (once you're about to touch code)
	12. apps/invoice-be/README.md, apps/invoice-be/agents/README.md
	13. apps/invoice-fe/README.md
	14. apps/invoice-website/README.md
	15. infra/README.md, infra/BICEP_GUIDE.md

8. Roadmap/QA (optional, situational)
	16. docs/guides/implementation_plan_updated.md — week-by-week sequencing (Month 1/2/3 sub-plans were retired 2026-07-27; current status lives in the *_features_tracker.md files instead)
	17. docs/test_cases/*.md — QA reference
	18. docs/guides/local_uv_setup.md — only when you're actually about to run it locally

Steps 1-7 are the ones that actually matter for "understanding the application." 8 is there when you get to frontend/website/ops work specifically. For current build status and open work, the *_features_tracker.md files in step 4-6 are the single source of truth — the architecture docs and individual feature files describe the target design only.
