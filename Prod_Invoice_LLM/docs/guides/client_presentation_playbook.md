## 1. Presentation Strategy & Tools Recommendation

### The #1 Rule
> *"Clients don't buy software. They buy a better version of their future."*

Your job is not to explain features. It is to **paint a vivid contrast** between the client's painful present (manual processing, errors, slow audits) and their frictionless future with Invoice AI.

## 2. The Art of the Presentation — Psychology & Flow

### The 4-Phase Winning Structure

```
PHASE 1 — PROBLEM VALIDATION (Empathy)    → Minutes 0-5
  Make the client feel SEEN.
  Never open with your product.
  Open with THEIR pain.

PHASE 2 — SOLUTION REVEAL (Hope)          → Minutes 6-15
  Reveal the platform as the cure.
  Keep it visual, not textual.
  Show ROI numbers, not features.

PHASE 3 — LIVE PROOF (Belief)             → Minutes 16-25
  Switch to the live demo.
  Let the product speak.
  Surprise them — don't just show expected screens.

PHASE 4 — DECISION TRIGGER (Action)       → Minutes 26-30
  Price, plan, and next step.
  Create mild urgency (limited pilot slots, Q4 intake).
  End with a question: "What would need to be true for you to move forward?"
```

### The Three Emotions You Must Create

| Emotion | How to Trigger It | In Which Phase |
|---|---|---|
| **Frustration** (at the status quo) | Tell their story back to them. Show the "before" screenshot. | Phase 1 |
| **Excitement** (at what's possible) | Show the Dashboard KPI screen loading in under 2 seconds. | Phase 2 |
| **Trust** (in your team) | Explain that no LLM ever does the math. Show the deterministic code principle. | Phase 3 |

## 10. Technical Deep-Dive for Engineering Audiences

When the client's CTO or IT Architect wants more than slides, use this 20-minute technical session:

### 10.1 Architecture Overview (5 minutes)
Show the system architecture diagram from `master_technical_guide_part2.md`:
- Azure Container Apps (microservices, auto-scaling)
- Azure Front Door + WAF (network security, global routing)
- FastAPI backend with LangGraph agent orchestration
- PostgreSQL Flexible Server + Redis Cache + Azure Blob Storage
- ChromaDB vector store with per-tenant isolated collections
- Azure Document Intelligence + Azure OpenAI Service

### 10.2 Data Flow Walkthrough (5 minutes)
Walk through the invoice processing pipeline step by step:
1. Document enters via email HMAC webhook or REST API
2. SHA-256 hash check for deduplication
3. Azure Blob upload → Azure Queue message enqueued
4. Queue Worker dequeues → NOVA LangGraph graph executes
5. Azure Document Intelligence OCR → LLM extraction schema
6. SENTINEL verification (pure Python Decimal, no LLM)
7. Alert flagging → Audit queue or auto-complete
8. ChromaDB indexing (BAAI/bge-m3 embeddings, 1024 dimensions)
9. Webhook delivery to ERP

### 10.3 Multi-Tenant Isolation Proof (5 minutes)
Demonstrate the four isolation layers:
- **SQL**: Show every query includes `WHERE tenant_id = :tenant_id` + AST validation
- **Vector DB**: `invoice_chunks_{tenant_id}` — collection names are structurally isolated
- **Blob**: `invoices/{tenant_id}/{invoice_id}/document.pdf` — path-scoped SAS tokens
- **API Keys**: PBKDF2-HMAC-SHA256 hash + per-key salt — database dump is useless

### 10.4 AI Boundary Explanation (5 minutes)
The hardest thing for engineers to believe: the AI doesn't do the math.
- **NOVA**: LLM outputs structured JSON only — field names and text values
- **SENTINEL**: Pure Python: `expected = sum(item.amount for item in items)`
- **SAGE SQL**: LLM generates SQL text, AST parser validates it, PostgreSQL executes it
- **SAGE RAG**: LLM narrates retrieved chunks — never synthesizes financial totals
