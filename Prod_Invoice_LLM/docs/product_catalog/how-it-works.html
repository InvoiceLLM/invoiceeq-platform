The pipeline

Five stages. Each with
a defined contract.

Anything that fails its contract stops and is routed to a human — it is never guessed at. Every stage is independently auditable, independently replaceable, and independently testable.

1
Intake

InvoiceEQ receives the document — via configured email mailbox, Google Drive / Salesforce sync, direct upload through the web interface, or the REST API. File headers are validated at the byte level immediately on receipt: file type is confirmed from magic bytes, not from the filename or MIME header a sender can falsify. A SHA-256 digest is computed before any further processing.

Contract: the document is genuine, deduplicated, and structurally valid before extraction begins.
2
NOVA Vision — Extraction

The document is read as a document, not as a fixed template. Azure Document Intelligence processes the visual layer — page geometry, text runs, table structures. A multi-pass LLM extraction step, bounded by a strict typed JSON schema, reads fields: header data (vendor, date, number, terms), line items (description, quantity, unit price, amount), and totals. All amounts are returned as exact decimal notation; all dates in ISO 8601. A moved field does not break the pipeline — extraction is position-independent.

Contract: extracted fields are typed, structured, and machine-verifiable. Plausible-but-unverifiable is not a valid output.
3
SENTINEL — Arithmetic Verification

SENTINEL rebuilds every total from the extracted line items using exact decimal arithmetic in deterministic code — no language model sits in this path. It checks: sum of line item amounts equals stated subtotal; subtotal plus tax minus any discount equals stated invoice total; tax amount corresponds to the applicable rate on the subtotal. Any discrepancy, at any check, issues a formal alert code and stops the invoice. There is no confidence band that overrides a failed arithmetic check.

Contract: every figure on the invoice either reconstructs from first principles or triggers a hard stop.
4
3-Way Reconciliation — Match Against PO and GR

A verified invoice is checked against the corresponding purchase order and goods receipt. Part numbers are aligned via vector similarity (tolerating supplier abbreviations). Billed quantities are reconciled against received quantities, tolerating partial shipments within a ±0.01 band. Price variances outside approved tolerance bands surface as exceptions. Retention clauses and holdback amounts are recognised as document structure, not arithmetic failures.

Contract: what was billed matches what was ordered and what was received, or a reconciliation exception is raised before posting.
5
Ledger Commit

An invoice that passes all four prior stages posts to the target ERP — SAP S/4HANA, Oracle Cloud, or NetSuite — with a complete audit trail attached: what was extracted, what was verified, which rules applied, which purchase order and goods receipt it matched, and who (if anyone) manually reviewed it. The audit trail is immutable and tenant-isolated. An invoice that fails any prior stage never reaches this step.

Contract: nothing posts to the ledger that has not passed arithmetic verification and three-way reconciliation.
Deployment

The 14-day production cutover.
What it actually contains.

14 days assumes a single entity on a standard ERP with credentials available on day one. What extends it is documented below — read it before committing to a timeline.

Phase 1
Days 1–3
Historical ingestion & baseline

Load past invoices from the customer's archive. Measure extraction accuracy against current ERP records — what InvoiceEQ reads vs. what the ERP already holds.

You end with: a measured baseline, not an estimate.
Phase 2
Days 4–7
Tuning against your suppliers

Vendor tolerances and extraction rules are set, then replayed against the historical corpus first. No rule reaches production without passing the 500-invoice replay.

You end with: rules proven against your own history.
Phase 3
Days 8–11
Connectors & matching

Mail and cloud intake channels configured. ERP write path tested against real purchase orders and goods receipts. Three-way match validated end-to-end.

You end with: a working path to your ledger.
Phase 4
Days 12–14
Controlled production cutover

Straight-through processing enabled for high-confidence suppliers first. Lower-confidence documents continue through manual review while the system learns. Scope is chosen by the customer.

You end with: live processing on a scope you chose.
What extends the 14 days
  • Custom ERP connectors beyond SAP, Oracle, and NetSuite
  • Multi-entity rollouts — each entity is effectively a separate deployment sequence
  • Environments where credentials or historical invoice data are not available on day one
  • Environments with on-premise-only ERP access requiring network path setup
