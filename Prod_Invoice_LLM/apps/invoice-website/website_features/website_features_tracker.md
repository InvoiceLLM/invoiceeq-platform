## Open Items / Gaps

- `[x]` **Gap 1: "See it in action" CTA linking to the flows visualizer** — flagged 2026-07-27, resolved 2026-07-28. Now formally documented as Feature 2 Tasks 2.5/2.6.

  **Total solution, end to end (so this is rebuildable from this description alone):**
  1. **Two entry points, both in `FlowsShowcaseSection.tsx`**: a "Launch Live Simulator" button (`onClick={() => onOpenModal("inbound")}`) that opens `FlowsModal` pre-selected to the Inbound flow, and a "Full Tab" `<a href={flowsUrl} target="_blank">` that navigates away entirely. Each of the 4 flow tiles below (Inbound/Outbound/Chat/Direction-Aware) also calls `onOpenModal(flow.id)` on click, opening the modal pre-selected to *that specific* flow.
  2. **`FlowsModal.tsx` is the shared viewer**: computes `flowsUrl = \`${FE_URL}/flows${initialFlowId ? \`?flow=${initialFlowId}\` : ""}\`` where `FE_URL = process.env.NEXT_PUBLIC_FE_URL || "http://localhost:3001"`. Renders this URL two ways simultaneously — a live `<iframe src={flowsUrl}>` for in-page preview, and an "Open Full Screen in New Tab" `<a href={flowsUrl} target="_blank">` for the same URL.
  3. **Deep-linking is read on the `invoice-fe` side**: `invoice-fe/app/flows/page.tsx` has a `useEffect` (added specifically for this) that reads `window.location.search` for a `flow`/`tab`/`type` query param on mount, normalizes it (`chat`/`rag` → `chat`; `outbound`/`vendor` → `outbound`; `vendor_chat`/`direction_aware`/`direction` → `vendor_chat`; `inbound` → `inbound`), and sets the page's `flowId` state accordingly — so `?flow=chat` opens the flows page directly on the Chat tab instead of defaulting to Inbound.
  4. **Why cross-origin, not an internal `<Link>`**: `invoice-website` and `invoice-fe` are separate Next.js deployments with no shared routing between them — the only way to navigate between them is a real browser navigation (`<a href>`/`window.location`) or an iframe, both of which need the full origin URL, hence `NEXT_PUBLIC_FE_URL` rather than a relative path.
  5. **Auth**: none needed. `/flows` has no `middleware.ts`/Clerk gate in `invoice-fe` and is deliberately excluded from the authenticated app's Sidebar/Header (`components/layout/Shell.tsx`'s `STANDALONE_ROUTES` allowlist, Gap 62) — it's meant to be a public, no-login demo reachable directly from the marketing site.
  6. **What's still open, tracked separately**: the actual value of `NEXT_PUBLIC_FE_URL` needs to be a real Azure FQDN in production, which depends on Gap 6 (Docker build-arg wiring) and Gap 5 (a Dockerfile/bicep module for `invoice-website` to even be deployed at all) — this CTA is code-complete but not yet deployable to Azure for the same infra reasons as the rest of Feature 4.
