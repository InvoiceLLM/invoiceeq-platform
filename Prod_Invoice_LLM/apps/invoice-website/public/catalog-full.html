The problem

Two approaches. One shared
failure point.

Both template OCR and general-purpose AI extract invoice data and produce a number. Neither independently verifies that number is correct.

Template OCR — ABBYY, Kofax

"Reads positions, not documents."

A supplier moves a field two centimetres and the template stops matching. Character confusion between "O" and "0" creates an invoice number that looks right but fails the ERP duplicate check silently.

→ layout drift → silent extraction error → duplicate payment risk
General-purpose LLM Extraction

"Produces plausible numbers."

A language model generates the most probable digits. When line items and tax don't reconcile, it produces a figure that makes the arithmetic look right — formatted identically to a correct answer, no uncertainty signal.

→ confident wrong answer · styled identically to a correct one

How it works

Five stages. Each with a contract.
Failure stops — never guesses.

Each stage defines what it accepts, what it produces, and what it does when something falls short. The answer is always "route to a human" — never "proceed with low confidence."

1
Intake — Document arrives SHA-256

Invoice received via email, Google Drive sync, manual upload, or REST API. File type confirmed from magic bytes (not filename). SHA-256 hash computed immediately — a duplicate is caught before any OCR or AI token is spent.

Contract: document is genuine, deduplicated, and structurally valid before extraction begins.
2
NOVA — Extraction 99.3% accuracy

Azure Document Intelligence reads page geometry, text, and tables. A typed JSON schema bounds the LLM extraction — amounts return as exact decimal, dates as ISO 8601. A field that moves on the page does not break extraction because NOVA reads structure, not position.

Contract: all fields are typed and structured. "Plausible but unverifiable" is not a valid output.
3
SENTINEL — Arithmetic Verification 0% hallucination

Exact decimal code (not a model) rebuilds every total: Σ(line amounts) = subtotal, subtotal + tax − discount = invoice total, tax vs. applicable rate. Any discrepancy triggers a formal alert code and stops the invoice. No confidence band overrides a failed check.

Contract: every figure either reconstructs from first principles or generates a hard stop.
4
3-Way Reconciliation Vector matching

Verified invoice matched against purchase order and goods receipt. Part descriptions aligned via vector similarity (tolerates abbreviations). Partial deliveries reconciled at dock-receipt level. Retention and holdback recognised as document structure.

Contract: what was billed matches what was ordered and received, or a reconciliation exception is raised before posting.
5
Ledger Commit — Post to ERP SAP · Oracle · NetSuite

Passes all four stages → posts to ERP with a complete, immutable audit trail: what was extracted, which rule applied, which PO it matched, who reviewed it. An invoice that fails any prior stage never reaches this step.

Contract: nothing posts to the ledger without passing arithmetic verification and three-way matching.

Security & compliance

Isolation is structural,
not a configuration setting.

Every property below is enforced at the architecture layer. Cross-tenant reads are not expressible in the system's query model — not merely forbidden by an application rule.

Row-Level DB Isolation

Mandatory tenant predicate injected at ORM layer on every query. Cross-tenant read is not expressible — not merely forbidden.

Partitioned Vector Indices

Each tenant's embeddings live in a physically separate namespace. A SAGE query from Tenant A cannot traverse Tenant B's data.

Ephemeral Storage Tokens

Document files accessed via signed URLs with 15-minute lifetime. No public buckets. A captured URL expires before it can be misused.

Zero Training Retention

No invoice data used to improve AI models. Architecture — not a contractual opt-out sitting on top of a pipeline that could change.

Hard Delete — Complete Purge

Deletion removes from every store atomically: relational DB, vector index, blob storage. Deleted records cannot reappear in SAGE answers.

RS256 Asymmetric Auth

Session tokens use RS256 + JWKS caching + issuer pinning. API keys stored as PBKDF2-HMAC-SHA256 hashes — plaintext never retained.

Enterprise scenarios

Six industries. The same failure
pattern, different surfaces.

Manufacturing
Multi-entity manufacturer
38,000 inv/mo · 4,200 suppliers · 3 countries
What breaks today

Three countries = three tax regimes. Invoices misrouted to the wrong jurisdiction process under the wrong tax treatment — manual correction required at every period close.

How InvoiceEQ addresses it

Jurisdiction read per document from the extracted supplier address — not a routing rule someone assigned. SENTINEL applies the correct rate automatically.

Automotive supply chain
Tier-1 automotive supplier
900 suppliers · 60,000 part numbers · JIT
What breaks today

Invoice says "WGT-A3-REV2"; PO says "Widget Assembly A3 (Revision 2)". Exact-string matching fails. At 60,000 part numbers this is a full-time job. Partial JIT deliveries create false quantity mismatches.

How InvoiceEQ addresses it

Vector similarity matches supplier descriptions to PO lines without identical strings. Partial deliveries reconcile against dock receipts, not the full PO quantity.

Construction & EPC
Infrastructure contractor
Progress billing · retention · subcontractors
What breaks today

Standard 5–10% retention looks like an arithmetic mismatch to any system that doesn't understand construction billing. Every progress claim becomes an exception.

How InvoiceEQ addresses it

Retention is recognised as document structure — a specific deduction type with defined treatment. A correctly-drawn progress claim verifies and posts without manual review.

Regulated industry
Pharmaceutical distribution
Controlled supply chain · high SKU count
What breaks today

Audits sample ~30 from 45,000/month. The 44,970 unchecked are unquantified exposure — any systematic error is invisible until an external audit surfaces it.

How InvoiceEQ addresses it

100% population coverage. Every invoice audited. Complete, immutable trail for every record — accessible directly, no IT data extract needed.

Honest limits

When InvoiceEQ is the wrong choice.

Every vendor says yes to everything — which is why buyers stop trusting what vendors say. Stating this clearly is the only reason the rest of this catalogue should be believed.

01
No purchase orders. Three-way matching requires a PO and goods receipt. Without them you get arithmetic verification + duplicate detection — not the matching layer that drives the highest STP bands.
02
Under ~500 invoices/month. At that volume a competent person is cheaper than any software. The economics only change above approximately 500 documents a month.
03
Already live on Coupa or Ariba. Displacing a working procure-to-pay suite is a renewal conversation, not a capability-gap one. Don't start that evaluation mid-contract.
04
Policy mandates on-premise hardware. This is cloud-native on Azure. Regional cloud deployment can be discussed; on-premise hardware cannot.
